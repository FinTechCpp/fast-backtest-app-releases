Fonctionnalités

Backtesting Rapide via C++

L'execution d'un backtest est extrêmement rapide grâce à l'utilisation de C++. Il est possible d'executer un backtest sur plusieurs années en moins de 5 secondes.

Interface Utilisateur multi plateforme Qt6

Grâce à Qt6, l'interface utilisateur est fluide et intuitive, offrant une expérience optimale sur toutes les plateformes. Les utilisateurs peuvent profiter d'une interface cohérente, que ce soit sur Windows, macOS ou Linux.

Analyse Détaillée sur un graphe ChartDirector

Utilisation d'une librairie de graphiques ChartDirector pour des visualisations avancées des résultats de backtest.

Installation

Instructions d'installation et de lancement par plateforme :

  • Windows (64-bit)

    Téléchargez le fichier ZIP, décompressez-le dans un dossier. Le binaire s'appelle backtestapp.exe. Double-cliquez sur l'exécutable ou lancez-le depuis PowerShell :

    cd C:\chemin\vers\fast-backtest-app-windows
.\backtestapp.exe

    Le fichier de configuration par défaut backtest_config.ini peut être édité dans le même dossier.

  • macOS (Intel & Apple Silicon)

    Téléchargez le DMG, montez-le puis glissez-déposez FastBacktestApp.app dans le dossier /Applications. Pour lancer :

    open /Applications/FastBacktestApp.app

    Si macOS bloque l'ouverture, autorisez l'application via Sécurité et confidentialité → Autoriser quand même.

  • Linux (Debian/Ubuntu)

    Téléchargez l'archive .tar.gz et extrayez-la :

    tar -xzf fast-backtest-app-linux-*.tar.gz
cd fast-backtest-app-linux
./backtestapp.sh

    Le script backtestapp.sh configure LD_LIBRARY_PATH et QT_PLUGIN_PATH pour utiliser les bibliothèques fournies. Assurez-vous que le script est exécutable (chmod +x backtestapp.sh).

Remarques :

  • Conservez le dossier distribué tel quel pour que les bibliothèques Qt et plugins soient trouvés correctement.
  • Si vous rencontrez des erreurs liées à des bibliothèques manquantes, vérifiez les fichiers fournis dans le dossier lib / plugins (Linux) ou la présence des DLL (Windows).

Support & Communauté

FAQ

Quelle est la différence entre la version stable et beta ?

Version Stable : Version testée et recommandée pour une utilisation en production. Elle a passé tous les tests et est considérée comme stable et fiable.

Version Beta : Version de développement avec les dernières fonctionnalités. Elle peut contenir des bugs et est destinée aux utilisateurs qui souhaitent tester les nouvelles fonctionnalités avant leur sortie officielle. À utiliser avec précaution.

Quelles plateformes sont supportées ?

Windows (64-bit), macOS (Intel & Apple Silicon) et Linux (Debian/Ubuntu). Utilisez les liens de la section Téléchargement pour chaque package.

Quel format pour les données OHLC ?

CSV avec colonnes Date, Open, High, Low, Close, Volume. La date peut être au format ISO (YYYY-MM-DD ou YYYY-MM-DD HH:MM:SS). Les en-têtes sont recommandés.

Comment lancer un backtest ?

Chargez votre fichier CSV via Fichier → Ouvrir, sélectionnez la stratégie et la période, puis cliquez sur "Lancer le backtest".

Où trouver les logs et la configuration ?

Les logs sont dans le dossier logs situé à côté de l'exécutable. Le fichier de configuration par défaut est backtest_config.ini dans le même dossier. Sur Linux, vérifiez aussi ~/.fast-backtest-app/ pour les configs utilisateur.

Comment mettre à jour l'application ?

Téléchargez la nouvelle version depuis la page de téléchargement et remplacez les fichiers. Conservez la structure du dossier fourni pour que Qt et les bibliothèques soient correctement résolues.

Signaler un bug

Avant d'ouvrir une issue, merci de vérifier la FAQ et les issues existantes.

  1. Rassembler les informations : version de l'application (Aide → À propos), système d'exploitation et architecture, fichier backtest_config.ini, extrait de données reproduisant le problème, captures d'écran et logs (dossier logs).
  2. Documenter la reproduction : étapes exactes pour reproduire, comportement attendu vs observé, messages d'erreur complets ou sortie terminal.
  3. Ouvrir une issue : Créez une nouvelle issue sur GitHub → https://github.com/FinTechCpp/fast-backtest-app-releases/issues. Collez les informations ci‑dessus et joignez les fichiers (logs, extrait CSV).
  4. Alternative : Si vous ne pouvez pas attacher de fichiers via GitHub, compressez-les et envoyez-les à support@fintechcpp.org en précisant le lien de l'issue ou le titre du problème.

Les rapports contenant une reproduction minimale et les logs sont traités en priorité.
